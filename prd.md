# PRD: Автоматизация сбора отзывов о приложении Halyk Kazakhstan

**Статус:** Согласовано, готово к реализации
**Дата:** 20.08.2026
**Автор:** подготовлено с Claude (Cowork) по запросу Лауры

## 1. Проблема и цель

Нужен автоматический, регулярно обновляемый свод отзывов о мобильном приложении «Halyk Kazakhstan» из App Store и Google Play, без ручного сбора вручную каждый раз. Отзывы должны копиться в одном файле на компьютере пользователя, с возможностью быстро увидеть новые и особенно негативные отзывы.

## 2. Область охвата (Scope)

- Источник 1 — **App Store (iOS)**: приложение «Halyk Kazakhstan», Apple ID **440635615** (https://apps.apple.com/ru/app/halyk-kazakhstan/id440635615).
- Источник 2 — **Google Play (Android)**: то же приложение, package name **`kz.kkb.homebank`** (https://play.google.com/store/apps/details?id=kz.kkb.homebank&hl=ru).
- Регионы/сторфронты: **только Казахстан** (сторфронт `kz` в App Store и Google Play). Уточнено пользователем 20.08.2026 — изначально рассматривались все доступные страны, но объём сузили до казахстанского сторфронта.
- Только **открытые, публично доступные источники данных** — без использования App Store Connect API или Google Play Developer API и без сервисных ключей разработчика:
  - iOS — публичный RSS-фид отзывов App Store (`itunes.apple.com/{country}/rss/customerreviews/id=.../json`), доступен без авторизации.
  - Android — открытый парсинг страницы отзывов Google Play (публичная веб-страница, без официального API).
- Рассылка по email — **исключена из объёма работ** (было в первоначальном запросе, отменено пользователем).

## 3. Пользовательская история

Как пользователь, я хочу, чтобы каждый день на моём компьютере автоматически обновлялся файл со всеми новыми отзывами о приложении из App Store и Google Play, с выделением негативных отзывов, — чтобы не заходить в сторы вручную и не пропускать проблемные отзывы.

## 4. Функциональные требования

1. **Сбор данных**: ежедневный опрос обоих источников (Windows Task Scheduler, 9:00). За один запуск по каждому источнику забирается не более **30 последних отзывов** (сортировка по новизне); уже сохранённые пропускаются. Уточнено пользователем 20.08.2026 — вместо полной истории источники ограничены топ-30 последних отзывов.
2. **Дедупликация**: при каждом запуске в файл добавляются только новые отзывы, ранее не сохранённые (уникальность — по ID отзыва для App Store; по устойчивому хэшу автор+дата+текст для Google Play, так как публичная страница не всегда отдаёт стабильный ID).
3. **Хранение**: единый локальный файл на компьютере пользователя (устройство **mmpc**), в папке **Desktop/GrowVibeProjects**. Файл не пересоздаётся — новые строки добавляются к существующим.
4. **Формат файла**: таблица (.xlsx) со столбцами:
   - Дата отзыва
   - Стор (App Store / Google Play)
   - Страна/сторфронт
   - Рейтинг (1–5)
   - Заголовок отзыва
   - Текст отзыва
   - Автор (никнейм, если доступен)
   - Версия приложения (если доступна)
   - ID/хэш отзыва (служебное поле для дедупликации)
   - Флаг «Негативный» (да/нет)
5. **Выделение негативных отзывов**: отзывы с рейтингом **≤ 3 ★** помечаются флагом «Негативный» и выделяются заливкой строки на том же листе (отдельный лист «Негатив» не используется).
6. **Уведомление**: без email-рассылки. После каждого запуска, если найдены новые отзывы с рейтингом ≤3★, скрипт показывает системное **Windows toast-уведомление** с числом новых негативных отзывов. Если негатива нет — уведомление не показывается.

## 5. Техническая архитектура

- Автоматизация — это **полностью локальный скрипт** (Python), запускаемый на устройстве **mmpc** через **Windows Task Scheduler** ежедневно в **9:00**.
- Скрипт работает без участия облака Cowork и без device bridge: не требует, чтобы приложение Claude было открыто или подключено к сессии. Единственное требование — компьютер включён и есть доступ в интернет в момент запуска.
- Каждый запуск скрипта:
  1. Забирает отзывы из App Store RSS и с публичной страницы Google Play (`kz.kkb.homebank`) по всем доступным странам.
  2. Сравнивает с уже сохранёнными записями (дедупликация).
  3. Дописывает новые строки напрямую в файл `Desktop/GrowVibeProjects/otzyvy_halyk.xlsx` на диске.
  4. Если среди новых строк есть отзывы с рейтингом ≤3★ — показывает Windows toast-уведомление с их количеством.
- Такая архитектура снимает риск «mmpc не подключён к Cowork в момент расписания», описанный в предыдущей версии PRD: скрипт исполняется прямо на машине пользователя, а не в облаке.

**Обновление 21.08.2026** — добавлено облачное расписание: пользователь потребовал, чтобы данные обновлялись каждое утро в 9:00, даже если компьютер mmpc выключен. Локальный запуск в принципе не может это гарантировать, поэтому добавлен второй, облачный контур:

- **GitHub Actions** ([.github/workflows/collect-reviews.yml](.github/workflows/collect-reviews.yml)) — расписание `cron: "0 4 * * *"` (04:00 UTC = 09:00 Asia/Almaty), плюс ручной запуск (`workflow_dispatch`).
- Джоб на GitHub-раннере: устанавливает зависимости из `requirements.txt`, запускает `collect_reviews.py` и `generate_page.py`, коммитит и пушит изменения в `otzyvy_halyk.xlsx` и `docs/index.html`, если появились новые отзывы. Push публикуемого GitHub Pages сайта происходит автоматически при изменении `docs/`.
- Работает независимо от состояния компьютера пользователя — единственное ограничение GitHub Actions: cron может отключаться при отсутствии активности в репозитории >60 дней (нужно периодически проверять).
- Windows toast-уведомление недоступно на облачном раннере (нет десктопа) — на этом контуре уведомление о негативе просто не показывается; это только для локального запуска на mmpc.
- Локальная задача Task Scheduler на mmpc (см. выше) оставлена как есть — она параллельно обновляет локальный xlsx и показывает toast, но не трогает git/GitHub. Это не создаёт конфликтов, т.к. она не пушит в репозиторий.

**Обновление 31.08.2026** — расписание и рассылка переведены на будни:

- Cron изменён на `"0 3 * * 1-5"` (03:00 UTC = 08:00 Asia/Almaty, только Пн–Пт). В выходные скрипт не запускается.
- Сбор при обычном запуске (без `--days`) теперь идёт по дате, а не по фиксированному количеству: глубина `DAILY_LOOKBACK_DAYS = 4` дня, с запасом на разрыв пятница→понедельник (3 дня) и небольшой буфер. Раньше был фиксированный топ-30 «самых свежих», из-за чего часть отзывов за длинный перерыв могла не попасть в выборку — теперь этот риск закрыт.
- За счёт этого понедельничный запуск автоматически подхватывает и суммирует всё, что накопилось за субботу и воскресенье — отдельной логики для «выходных» не потребовалось, дедупликация и секция «НОВЫЕ» в файле делают это сами.
- Письмо теперь тоже условное: если `new_total != 0` — обычное письмо с вложением xlsx; если `new_total == 0` (в рабочий день не появилось ни одного нового отзыва) — короткое письмо без вложения: «Новых отзывов за сегодня не было.».

## 6. Нефункциональные требования

- Сбор через открытые источники не требует ключей/сервисных аккаунтов, но:
  - Открытый парсинг Google Play официально не поддерживается Google и может измениться или быть заблokирован — требует периодической проверки/поддержки скрипта.
  - Публичный RSS App Store — официальный публичный механизм Apple, более стабилен.
- Обработка ошибок: если один из источников недоступен при запуске, второй источник всё равно должен успешно обновиться; ошибка логируется, не должна прерывать весь процесс.
- Файл должен расти без потери исторических данных (никаких перезаписей/удалений существующих строк).

## 7. Вне рамок (Out of scope)

- Рассылка по корпоративной или личной почте.
- Использование официальных App Store Connect API / Google Play Developer API и связанных ключей разработчика.
- Анализ тональности (sentiment analysis) сверх простого деления по рейтингу ≤3★.
- Перевод отзывов на другой язык.

## 8. Открытые вопросы — решения (зафиксировано 20.08.2026)

1. **Офлайн mmpc**: снято архитектурным решением — скрипт полностью локальный (Windows Task Scheduler, 9:00 ежедневно), не зависит от подключения к Cowork. См. раздел 5.
2. **Push-уведомление**: да — Windows toast-уведомление с числом новых негативных отзывов после каждого запуска, при их наличии.
3. **Выделение негатива**: заливка строк на одном (основном) листе.
4. **Package name Google Play**: `kz.kkb.homebank`.
5. **Глубина сбора**: изменено 20.08.2026 — вместо полной истории собираются только **топ-30 последних отзывов** по каждому источнику за запуск (см. п.4.1).

## 9. Критерии приёмки

- После первого запуска в файле `otzyvy_halyk.xlsx` присутствуют отзывы из App Store и Google Play с корректными полями.
- При повторном запуске в тот же день без новых отзывов файл не создаёт дублей.
- Отзывы с рейтингом ≤3★ визуально отличимы от остальных.
- Файл сохраняется и обновляется в `Desktop/GrowVibeProjects` на устройстве mmpc.
